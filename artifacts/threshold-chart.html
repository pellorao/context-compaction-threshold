DeepSeek Best Compaction Threshold

DeepSeek 最佳压缩阈值

最佳阈值取决于缓存价格、摘要长度、上下文增长速度、压缩耗时以及工作所需的最低上下文。不同用户在成本、速度和可用上下文之间接受的程度不同，因此适合的阈值也会不同。

我们做了什么

先从真实工作会话提取请求和上下文增长，再重采样出更多等价工作负载，并用实际压缩数据计算不同阈值下的费用与耗时。

  1. 提取工作负载对 DeepSeek Flash 的真实请求和上下文增长进行逐请求分析。
  2. 测量压缩用 9 次真实压缩的输入、缓存前缀、摘要输出和耗时校准模型；其中 6 次把真实会话上下文按语义裁剪到较小压缩点，3 次是当前会话的原生压缩。
  3. 经验重采样把每个真实 session 的连续请求变化按 8 个请求一块做 circular block bootstrap，用固定随机种子生成 100 组工作负载。
  4. 重放并取期望在每组重采样序列上逐阈值重放，再对 100 组费用和压缩时间取平均，不对最终曲线另做平滑。

公式与变量

先计算一次请求的价格，再把普通请求和压缩事件在整个工作负载上累加。

单次请求费用 Q(x, c, y) = p_m · [(1-c) + αc] · x + p_o · y 价格比例 α = p_c / p_m ρ = p_o / p_m B = (1-β) + αβ 总费用 J(T) = Σ Q(普通请求) + Σ Q(压缩输入与摘要输出) 单次压缩耗时 t_c = a · (C - K) + G / v 时间占比 N_c(T) · t_c(T) / [W + N_c(T) · t_c(T)] 稳态近似 T* ≈ R + √( 2Δ · (BR + ρG) / α )
x单次请求输入中的上下文 token 数。
y该次请求生成的输出 token 数，按输出价格计费。
c普通请求输入中命中前缀缓存的比例。
p_m / p_c / p_o每 token 的缓存未命中输入、缓存命中输入和输出价格。
α缓存输入相对未缓存输入的价格比例；DeepSeek 当前为 0.02。
ρ输出相对未缓存输入的价格比例；DeepSeek 当前为 4。
B一段普通上下文按缓存命中率折算后的有效单位价格。
C / KC 是压缩请求的输入 token；K 是可复用的缓存前缀 token。
T / RT 是压缩阈值；R 是压缩后的有效上下文基线。
Δ每个普通请求之后，上下文平均增加多少 token。
G每次压缩实际生成并计费的摘要输出 token 数。
β压缩输入中命中缓存的比例，按固定前缀建模为 β = min(1, K/C)。
a未缓存输入的预处理时间，单位为秒 / token；由真实压缩耗时拟合。
v摘要生成的有效输出速度，单位为 token / 秒；图中滑块按比例改变这一项。
N_c / t_c / W压缩次数、单次压缩耗时、不含压缩的正常工作时间。

各因素如何移动最佳阈值

  • 缓存输入越便宜，阈值越高
    α 越小，长期保留上下文的边际成本越低。
  • 每请求增长越快，阈值越高
    Δ 越大，低阈值会造成更频繁的压缩。
  • 摘要越长，阈值越高
    G 越大，每次压缩的输出费用越高。
  • 工作最低上下文越高，可选阈值越高
    最终还要满足实际工作可接受的最小有效上下文。
  • 输出越慢，可用阈值越高
    v 越小，摘要生成段越长，为控制时间占比就需要减少压缩次数。

9 次真实压缩对耗时模型的双因素拟合为 R² = 0.980；只使用摘要输出时仍为 R² = 0.951，只使用输入时仅 R² = 0.203。闭式公式用于解释变化方向；页面曲线在 100 组经验重采样工作负载上逐请求重放并取期望，因此保留了真实请求顺序、上下文增长和压缩时点。这里的 v 是图表上方滑块控制的“服务端输出速度”，只描述压缩摘要的生成段；默认值 167.5 tok/s 来自这 9 次真实压缩对摘要生成耗时的拟合，并不是整个请求端到端的总 token/s。滑块只调整摘要生成时间，不改变输入处理时间和费用。

适用范围与注意事项

  • 部分数据是插值模拟
    请求和上下文来自实际会话，阈值下的压缩费用与耗时由实测压缩数据插值得出，不是在历史会话中直接观测到的结果。
  • 压缩样本仍然较少
    9 次真实校准中的摘要长度和缓存前缀仍有波动，区间表示这些实测变化，不是统计置信区间。
  • 阈值依赖具体工作方式
    如果工作需要长期保留超过 200K 的上下文，应优先满足该下限，再比较相应区间的费用和压缩时间。
  • 重采样不能代表所有未来负载
    曲线使用真实请求变化块生成 100 组经验重采样序列，只能覆盖样本中的变化模式；工作分布变化后应重新采样。
