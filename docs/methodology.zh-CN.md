# 方法与统计数据

本文记录项目的固定规则和各个 profile 的数据统计。README 保持简短，只指向这里。统计数据来自生成的 `result.json`。维护者机器上的 Claude Code 对话记录还在增长，重新运行会得到略有不同的数字。

## 固定规则

### 阈值网格

- 阈值是触发压缩时的上下文大小，单位是 token。
- 所有 profile 的网格步长都是 **2000 token**。已发布的 DeepSeek 曲线本来就是 2000。这是项目规则，不是各模型自己的选择，有测试检查。
- 网格下限是能设置的最小触发点。网格上限是**最大有效触发点 = 最大设置值 - 实测缓冲**。如果某个模型的这个最大值无法从权威来源核实，就不填该 profile 的横轴上限，把问题交给维护者。
- Codex 上的 DeepSeek Flash 保持已发布的横轴，64K 到 900K。Codex 没有“窗口加缓冲”这种设置，所以它的页面只显示触发点。

### Claude Code 的触发点（Opus 5.5、Sonnet 5.5）

设置项是 `autoCompactWindow`（全局，或在 `modelSettings` 下按模型设置）。

| 事实 | 取值 | 来源 |
|---|---|---|
| 允许的窗口 | 100K 到 1M token | Claude Code 设置参考中的 `modelSettings.autoCompactWindow`（“a number of tokens from 100000 to 1000000”）；模型配置页面；已安装的 Claude Code 2.1.316 内的设置说明 |
| 模型上下文窗口 | Opus 5.5 和 Sonnet 5.5：1M | claude-api skill 的 Current Models 表（1M 上下文，128K 最大输出）；Claude Code 模型配置页面（Opus 4.7 及以后、Sonnet 5 及以后默认使用 1M 窗口） |
| 窗口上限 | 有效窗口取设置值与模型窗口中较小的一个 | 模型配置页面（Claude Code 把它限制在模型自身的上下文窗口内） |
| 缓冲 | 33K | 文档：1M 窗口下“Sessions auto-compact at about 967K tokens by default”。已安装的 Claude Code：触发点 = 窗口 - min(最大输出, 20K) - 13K = 窗口 - 33K。日志：在记录这些会话时设置的 300K 窗口下，自动压缩输入的中位数是 267.9K（Opus 和 Sonnet 都是），即实测缓冲 32.1K |

由此得到：

- 最小触发点 = 100K - 33K = **67K**。最大触发点 = 1M - 33K = **967K**。
- 网格：67K、69K……967K。每个网格点对应一个整数窗口：`autoCompactWindow = 触发点 + 33000`，从 100000 到 1000000，步长 2000。页面和悬停提示都会显示所选触发点对应的窗口值。
- 两个模型的缓冲相同，因为缓冲只通过 `min(最大输出, 20K)` 与模型有关，而两者的最大输出都是 128K。日志里没有记录每次压缩时生效的窗口，所以实测缓冲假设记录这些会话时设置的是 300K 窗口。
- 这里无法验证的一点：所有套餐是否都能为这两个模型使用 1M 窗口。文档没有限制，300K 及以下的窗口有日志佐证。

### 费用轴：每 100 万个计费 token 的费用

每个 profile 的费用轴都做了归一化，这样不论分析了多少历史数据，图都能互相比较。

- 真实历史的计费 token 数 `N` = 普通输入 + 缓存写入（5 分钟和 1 小时）+ 缓存读取 + 输出，对所有纳入且去重后的请求求和。每个 profile 一个常数，由历史数据算出，保存在 `result.json` 的 `snapshot.billed_tokens`，构成保存在 `snapshot.billing_mix`。
- 某个阈值下画出的费用 = 该阈值下重放得到的总费用 /（`N` / 1,000,000）。除数**不是**该阈值下重放的 token 数，那个数会随阈值变化，会让曲线失真。
- 因此，作为基准的这一百万 token 具有这些会话真实的计费构成。所有费用数字都按它计算：图、悬停提示、快速选择、CSV 的 `expected_cost_usd_per_million_tokens` 列和下面的关键数字。`result.json` 同时保存总美元（`cost_usd_off_peak`）和归一化后的值（`cost_per_million_tokens`）。
- 压缩请求本身不计入 `N`（Claude Code 的对话记录里没有它们，Codex 里的压缩请求会被去掉，见下文），但计入重放费用。
- DeepSeek Flash 用同样的方式归一化。它最初发布的曲线是较小历史的总美元，没有 token 总数，所以用 Codex 会话重新计算过。

### 价格

费用先以普通输入价为单位计算，再换算成美元。价格单位是每百万 token。

| Profile | 输入 | 缓存写入 5 分钟 | 缓存写入 1 小时 | 缓存读取 | 输出 | 来源 |
|---|---|---|---|---|---|---|
| deepseek-flash | $0.15 | $0.15 | $0.15 | $0.003 | $0.60 | DeepSeek 闲时标价，沿用本项目第一个发布版本 |
| claude-opus-5-5 | $4 | $5 | $8 | $0.20 | $20 | claude-api skill：Current Models 表（$4 / $20）；prompt-caching Economics（5 分钟写入 1.25 倍，1 小时写入 2 倍，Opus 5.5 的读取是 0.05 倍） |
| claude-sonnet-5-5 | $2 | $2.50 | $4 | $0.20 | $10 | claude-api skill：Current Models 表（$2 / $10，缓存读取 $0.20）；写入倍数相同 |

比值 alpha（缓存读取 / 输入）分别是 0.02、0.05、0.1。比值 rho（输出 / 输入）分别是 4、5、5。

### 哪些会话和请求会被计入

Codex（`~/.codex/sessions`）：

- 提供方等于 profile 的提供方，或模型名以某个 profile 前缀开头的会话。
- 请求按 response ID 去重。
- 工作目录包含 `smoke`、`probe` 或 `test` 的会话被排除，用于测量压缩耗时的会话也被排除（`--exclude-thread`）。`--active-thread` 排除分析会话本身，并加入它最后一次压缩之后的最新一段。
- Codex 把每次真实压缩记成一个压缩请求，紧接着是一条 `compacted` 记录。这个请求会从会话里去掉（它不计入 `N`，压缩由重放自己建模），压缩前后的两段则像 Claude Code 那样（见下文）接成一条未压缩的请求流。没有这一步时，真实压缩处上下文骤降，会让重放的上下文变成负数，所有费用都变成负的。
- 提供方等于 profile 的提供方，或模型匹配的会话是候选；但只有它用到的每个模型都以某个 profile 前缀开头，才会被纳入。两个使用 `deepseek-v4-pro` 的会话（62 个请求）只因提供方相同而被匹配到，已按 `other-model` 排除：这个模型的价格不同。
- 工作时间是会话自己报告的各任务时长之和。其中包含真实压缩占用的秒数（每次约 20 到 30 秒，在含有这些压缩的那个长会话里不到 3%）。

Claude Code（`~/.claude/projects/**/*.jsonl`）：

- 只取模型名以 profile 前缀开头的 `assistant` 记录：`claude-opus-5-5`、`claude-sonnet-5-5`。其他版本，例如 `claude-opus-4-8`，因为价格不同而被排除。
- 请求按 `message.id` 全局去重。一个回复被拆成多行流式写入时只算一次，取最大的 `output_tokens`。消息 ID 会在不同文件间重复（分叉和恢复会话），所以去重跨所有文件。
- 子代理的对话记录也计入。它们用同样的机制压缩，并且占了大多数压缩（Opus 的 261 次中有 168 次）。
- 一个对话记录文件就是一个会话。没有匹配请求的文件被排除。
- 缓存写入 token 按每个会话真实的 5 分钟、1 小时写入构成计价，由此得到该会话的“未缓存 token 价格倍数”。
- 工作时间是一个会话内相邻匹配请求的间隔之和。超过 300 秒的间隔算空闲，并扣除压缩耗时。并行的子代理相加，所以时间占比是代理工作时间的占比，不是墙上时钟的占比。

### 如何找到压缩并校准

- Codex：手工测得的试验文件 `data/compaction_trials.json`。会话里的真实压缩只用来接续请求流，不用于校准。
- Claude Code：子类型为 `compact_boundary` 的 `system` 记录，带有 `compactMetadata`（触发方式、`preTokens`、`durationMs`）。摘要是紧随其后、标记为 `isCompactSummary` 的用户记录。边界按时间戳和 `preTokens` 去重。如果压缩前没有请求、没有耗时或大小、或没有摘要文本，这次压缩就不用于校准。
- 压缩请求本身不在对话记录里。它的输入是压缩前的整个上下文：除了一小段未缓存的尾部（`preTokens` 减去最后一次请求的上下文），全部是缓存读取；尾部按该会话的倍数作为缓存写入计价。
- 摘要 token 数由摘要文本估计。普通回答（只有文本，扣除思考 token）的输出 token 数，对汉字个数和其他字符个数做回归。
- 压缩耗时 `t_c = a * C + G / v` 在各次压缩上无截距拟合（`C` 是整个压缩输入，`G` 是摘要 token 数）。摘要 token 数服从 `G = g0 + g1 * C`。
- 压缩后的上下文及其未缓存部分，取每次压缩后第一个请求的中位数（Claude Code），或取实测值（DeepSeek）。
- 真实的自动压缩都发生在同一个水平（Claude Code 约 267K，Codex 约 300K），所以更高的触发点从未被观察到。每个会话被真实压缩切开的各段，会接成一条未压缩的请求流：后一段从前一段的上下文出发，加一个中位数增量，未缓存部分取中位数。因此约 267K 以上的曲线是外推得到的。
- 如果某个模型自己的压缩少于 50 次（harness 设置 `min_fit_compactions`），并且 profile 指定了 `borrow_calibration` 的来源 profile，拟合就同时用自己的压缩和来源模型的压缩。来源模型的耗时要乘以一个比值：该模型自己实测的总耗时，除以来源模型拟合结果对这些压缩的预测耗时。页面和下面的统计表都会标明这一点。没有来源模型时运行会停止。

### DeepSeek 2026-10-17 的模型更新

DeepSeek 在 2026-10-17 更新了 Flash（DeepSeek 价格页把它列为 `DeepSeek-V4.1-Flash-1017`）。在 Codex 会话上做了汇总检查：

| 时期 | 候选文件 | 请求 | 是否纳入 |
|---|---|---|---|
| 更新前（2026-09-30、2026-10-01） | 6 | 80 | 都没有，全是冒烟或测试会话 |
| 更新后（2026-10-30、2026-10-31） | 42 | 3,480 | 是（扣除上面的排除项） |

- 两个时期的每条请求记录字段完全相同（`input_tokens`、`cached_input_tokens`、`output_tokens`、`reasoning_output_tokens`、`cache_write_input_tokens`、`total_tokens`）。
- 计数口径也相同：`cached_input_tokens` 从不超过 `input_tokens`（输入包含缓存的部分），`total_tokens` 在每个请求里都等于输入加输出，`reasoning_output_tokens` 从不超过 `output_tokens`（推理算在输出里），`cache_write_input_tokens` 始终是 0，用量是逐请求的，不是累计的。
- 纳入的会话从头到尾都是 `deepseek-flash`。只有两个被排除的会话用了 `deepseek-v4-pro`。
- 所以纳入的数据全部来自更新之后，不需要按时期做归一化。以后如果两个时期的会话混在一起，应当按这些字段和模型 id 识别，而不是按日期。
- 价格：DeepSeek 当前价格页给 `deepseek-flash` 的闲时价是缓存命中 $0.003、缓存未命中 $0.15、输出 $0.60（每百万 token），与 profile 一致。页面没有说明更新前 Flash 的价格。更早数据的价格无从核对，但没有纳入更早的数据。留给维护者的问题：Flash 在 2026-10-17 之前的价格是否不同（只有以后纳入旧会话时才有影响）？

### 重采样

- 对每个会话真实的逐请求变化做循环分块自助法：块长 **8 个请求**，**100 次重复**，种子 **20261031**。
- 每个阈值在每次重复上重放，结果取平均。最终曲线不做平滑。
- 浅色范围：Claude 各 profile 取实测压缩波动的 10% 到 90% 分位，DeepSeek 取最小值到最大值。
- 自助法曲线低于真实会话的精确重放（在 `result.json` 里保存为 `exact_curves`）：在检查的几个点上，Opus 低 1% 到 6%，Sonnet 低 3% 到 13%，DeepSeek 在 2.5% 以内（高或低）。请更多地看曲线形状和最低点位置，而不是绝对数值。
